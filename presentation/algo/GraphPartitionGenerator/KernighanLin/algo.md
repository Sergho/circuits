# Алгоритм Кернигана–Лина (Kernighan–Lin)

Эвристический алгоритм разбиения графа на `k` частей, минимизирующий число
пересекающих границу рёбер за счёт жадных перестановок (swap) пар вершин из
разных частей. Реализованный вариант — упрощённый «жадный» KL: на каждом шаге
выбирается **глобально** пара с максимальным положительным приростом и сразу
выполняется её своп. Алгоритм останавливается, когда таких пар больше нет.

## Параметры

- `partsCount` — количество частей разбиения (обычно 2).

## Используемые понятия

- **Прирост (`gain`) пары `(u, v)`** — изменение `oldCut - newCut`, которое
  даст своп `u` и `v` между их частями. Считается в проекте методом
  `IGraphPartition.CalculateGain(u, v)` как:

  ```
  gain(u, v) = external(u) + external(v) - internal(u) - internal(v)
             - 2 * [есть ребро (u, v)]
  ```

  где `internal(x)` — число соседей `x`, лежащих в одной части с `x`, а
  `external(x)` — в других частях.

- **Кэш приростов (`cachedGains`)** — словарь `Edge → int` (ключ — нормализованное
  ребро между парой, не обязательно реально существующей в графе). В нём хранятся
  приросты всех пар вершин из **разных** частей, в текущий момент актуальные.

## Шаги

### 1. Создание начального разбиения

1. Создать `partition = new GraphPartition(graph, partsCount)`. При создании
   `GraphPartition` вершины автоматически распределяются по частям примерно
   поровну (последовательными блоками по индексам).

### 2. Заполнение кэша приростов

1. Перебрать все пары `(u, v)` из **разных** частей: для каждой пары
   рассчитать `partition.CalculateGain(u, v)` и положить в `cachedGains` с
   ключом `new Edge(u, v)`.

### 3. Случайное перемешивание начального разбиения

Чтобы стартовать не с детерминированного «блочного» разбиения, выполняется
несколько случайных свопов:

1. Для `i` от `1` до `verticesCount - 1`:
   - Выбрать случайный `j ∈ [i + 1, verticesCount)`.
   - Если вершины `i` и `j` лежат в одной части, пропустить.
   - Иначе вызвать `SwapVertices(i, j)` (см. шаг 5 ниже — это та же
     операция, что и в основном цикле, она обновляет кэш приростов).

> Замечание: эти стартовые свопы **не считаются** в `LastIterationsCount`.

### 4. Основной цикл

Сбросить `LastIterationsCount = 0`.

Повторять:

1. Найти в `cachedGains` пару с **максимальным положительным** приростом
   (`gain > 0`). Если такой пары нет — выйти из цикла.
2. Применить `SwapVertices(u, v)` — фактический своп пары и обновление кэша
   (см. шаг 5).
3. Увеличить `LastIterationsCount` на 1.

### 5. Своп пары `(u, v)` с обновлением кэша

1. Вызвать `partition.SwapVertices(u, v)` — вершины меняют части.
2. Обновить кэш для вершины `u`: для **каждой** другой вершины `w` графа:
   - Сформировать ключ `key = new Edge(u, w)`.
   - Если ключ уже есть в `cachedGains` — удалить запись.
   - Если ключа нет — добавить запись `cachedGains[key] = partition.CalculateGain(u, w)`.
3. Аналогично обновить кэш для вершины `v`.

Эффект: пары, для которых `u` (или `v`) и второй конец оказались **в разных
частях** (а до свопа были в одной), добавляются в кэш с новым значением приростa;
пары, которые **до свопа** были в разных частях и попали в кэш, а после свопа
оказались в одной, — удаляются из кэша.

### 6. Возврат результата

Вернуть `partition`.

## Свойства реализации

- **Жадный, без backtracking.** Классический KL делает «проход» (одну
  фазу): k свопов с накоплением приростов и затем откатывает до префикса
  с максимальным суммарным приростом. Здесь упрощённый вариант — каждый
  шаг сразу выполняет лучший своп.
- **Сходимость.** Каждый своп уменьшает `CrossEdgesCount` строго (т.к.
  берётся только `gain > 0`), и потому цикл всегда конечен.
- **`LastIterationsCount`** — число «полезных» свопов (без учёта
  стартовых перемешивающих).
- **Сложность.** Поиск максимума в кэше — `O(|cachedGains|)`. Обновление
  кэша после свопа — `O(n)` пересчётов приростов на вершину, каждое из
  которых — `O(deg)`.
- **Случайность.** `Random` инициализируется в конструкторе без seed, поэтому
  результат недетерминирован между запусками.

## Зависимости от других сущностей проекта

- `GraphPartition.CalculateGain` уже корректно учитывает наличие ребра между
  свопаемыми вершинами (поправка `-2`).
- `GraphPartition` сам распределяет вершины при создании, поэтому ручная
  инициализация частей не требуется.
- `Edge` имеет корректные `Equals` / `GetHashCode` по нормализованной форме,
  что делает его пригодным для использования в качестве ключа `Dictionary`.
